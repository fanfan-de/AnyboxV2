## 实际浏览器

运行 `npm run build`，再运行 `node tests/helpers/catalog-browser-host.mjs`，打开其输出的临时地址。该宿主使用真实应用组件，所有远端请求和凭据均为 mock；退出时通过 harness.close() 等待清理并删除临时数据库。

当前主要流程为：选择统一 Provider 定义 → 确认连接并填写 Key → 保存连接 → 自动展示适用模型。模型参数、自定义模型和多份参数预设位于高级设置，目录无需逐个“填写模型配置”。选择器提交稳定的执行配置 ID；公共定义和实际账号连接拥有不同身份。

统一定义接入阶段、此次界面整理前，在 Chrome 的临时 mock 宿主中选择 Anthropic QA，点击“配置 API Key”，填写测试 Key 与代理地址并保存后，Claude QA 自动显示为可用，基础配置显式保存 `maxOutputTokens=4096`；已弃用模型显示不适配原因，全程无需逐个保存目录模型。高级设置初始收起，另建 8K 参数配置后，原基础配置和相同远端 ID 的新配置同时保留。

新建会话并选择自动生成的 Claude QA 后，提交消息完成流式输出和 mock Bash 工具续轮，第一轮成功持久化；最终结果为 `Mock native final answer: catalog-tool-observed`。浏览器 warning/error 日志为空。实际来源/Key 权限仍由真实请求确认；本地 `available` 仅表示配置就绪。

目录刷新推进检查时间，未保存的连接名称和代理地址草稿仍保留。重载页面后，会话选择和已完成的结果恢复。测试完成后关闭临时浏览器页，宿主正常退出并删除临时数据库目录。

### 模型服务排布与交互整理

同日使用 Codex 内置浏览器和上述隔离宿主验证新版界面。默认页左侧列出账号连接，右侧显示所选连接的模型，目录仅在“添加提供方”流程出现。选择 Anthropic QA、填写名称、代理地址和测试 Key 后，一次保存即返回可用模型列表；再次选择同一 Provider 创建个人账号，原工作账号及参数预设独立保留。重载页面优先恢复记住的连接，无有效偏好时选择本地配置就绪的连接。

从当前表单另存 8192 输出预设，原基础配置仍为 4096；编辑预设至 12288 的未保存草稿在修改连接地址、替换 Key、删除 Key、刷新状态和切换账号后仍可恢复。删除 Key 后整组模型立即不可用。个人账号的未保存地址草稿与工作账号参数草稿独立；列表搜索可以定位预设，不可用筛选保留弃用原因。

新建自定义模型的名称、远端 ID 与 16384 参数在收起、刷新和账号往返后完整恢复；再次点击新建入口会恢复已有新草稿。新增 12288 参数预设同样保持独立编辑目标及固定模型关联，远端 ID 仍为只读。只有显式“放弃修改”才清除新草稿，原基础配置继续保留。

受控 HTTP 将预设的已存参数改为 10240 后，浏览器刷新仍保留 12288 草稿和原始修订号，保存返回冲突，不覆盖服务器的新参数；“放弃修改”恢复 10240，再编辑后可正常保存。新版冲突文案明确说明保留草稿与加载最新配置的操作。

窄屏下连接列表与主内容改为单列，目录和连接表单顺序排列；实际浏览器 DOM 检查未发现这些区域的横向溢出，选择提供方、返回连接及保存入口均可操作。浏览器 viewport 覆盖存在缩放差异，此次不将请求尺寸声明为精确设备尺寸。桌面截图见[连接与模型列表](ui/models-settings-connections.jpg)和[添加提供方](ui/models-settings-add-provider.jpg)。控制台无 warning/error。所有凭据和远端行为仍使用替身。
