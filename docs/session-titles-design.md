# Anybox Harness 会话自动命名实施计划

本计划为 Anybox Harness 增加类似 Codex 的会话命名流程：首次接受用户消息时保存输入摘要，服务端后台生成简短标题，再持久保存并通知所有客户端。用户不必点开会话，手动名称始终优先。状态为待实施；本次只制定计划。模型调用和按用途选模采用[通用内容生成设计](content-generation-design.md)。

当前 `Session.title` 已由服务端根据第一个已接受 Run 的原始输入派生，并通过列表和详情返回。下面的改造在此基础上增加持久标题、独立模型调用和手动改名，不改变 Session 对话树及 Run 的执行事实。

## 行为目标

| 场景 | 计划行为 |
| --- | --- |
| 空会话 | `title: null`，界面沿用短会话 ID 占位 |
| 首次接受 Run | 同事务保存输入摘要，最多 60 个 Unicode 字符；保存后台命名任务 |
| 后台生成成功 | 保存用户语言的单行标题，最多 36 个 Unicode 字符；侧栏、面板和分屏标签同步更新 |
| 首次 Run 失败或取消 | 已接受的输入仍可命名；标题任务独立于用户 Run 的取消信号 |
| 模型不可用、超时或返回无效内容 | 保留摘要；不影响用户 Run，不切换模型或账户 |
| 只有图片或文件 | 保留附件数量摘要；首期不为命名读取图片和文件正文 |
| 手动改名 | 保存最多 120 个 Unicode 字符的非空名称，之后不再自动覆盖 |
| 编辑首轮、重新生成或切换分支 | 保持会话名称，避免跟随当前查看路径变化 |
| 归档 | 取消或废弃自动命名任务；已归档会话只读，恢复不隐式重试 |

60、36 和 120 是本计划的产品限制，输入与输出均按 Unicode 码点计数。摘要折叠空白并在截断时添加省略号。模型输出去除外围引号、折叠空白并限制长度；工具调用、非正常完成或空输出视为失败，只保存合格的标题文本。

## 模型选择与参数

标题使用当前执行设备的内容生成默认模型，或用户在“会话标题”用途中选择的覆盖配置。设置由通用内容生成组件持有，不属于 Session 或 Agent。未配置、关闭或配置失效时保留摘要，不静默借用首次 Run 的模型或切换账户。

标题组件调用通用生成端口，不直接管理协议或模型 execution。通用服务复用已有 `ModelConfiguration` 和 `models.openNative()`，原样使用已保存的能力与原生参数，并显式选择完整的非流式响应。用途模型在生成准入时固定，Models 在 execution 打开时捕获配置；后续修改不影响在途调用。

Responses 和 Anthropic 的配置参数可能包含服务端搜索，空的本地工具声明不能关闭它。通用服务拒绝已启用搜索的配置，标题保留摘要并记录原因。用户可使用已有高级参数预设创建 `baseline: false` 的专用生成配置，显式保存短输出、无搜索和支持的推理设置。

生成速度、token 上限和推理行为取决于选择及保存的配置。建议使用适合短文本的模型；不能在截止时间内产出标题时仍按失败回退。Models 首期增加明确的单次非流式传输选择，保持原生参数和历史契约。

## 数据与事务

在 Session 沿用的 `run-state` 迁移账本中新增 v9，复用现有业务 SQLite 连接。

Session 增加持久字段 `title`、`titleSource` 和 `titleRevision`。来源为 `fallback`、`generated` 或 `manual`，空会话可为空；修订号用于条件更新和客户端合并。内容生成设置使用独立迁移域，Session 不保存或查询用途模型设置。

Session 独占标题任务表，记录 Session ID、首个 Run ID、任务令牌、预期标题修订号、状态、时间和固定失败类别。生成成功后记录返回的模型配置 ID 与设置修订号作为任务元数据，不直接读取通用设置表；失败或中断时这两个字段可为空，首期不要求完整执行审计。状态区分 `pending`、`running`、`completed`、`skipped`、`failed`、`interrupted` 和 `superseded`。首期每个会话最多一个自动任务。任务引用已有原始输入，不复制对话历史、凭据、认证头、执行句柄或原生请求响应。

`registerRun()` 的接受事务完成以下操作：

1. 优先处理已有幂等结果，重复请求不创建任务。
2. 第一次真实接受 Run 时保存摘要，并为尚未手动命名的会话插入唯一任务。
3. 固定该任务的来源 Run；并发根 Run 由事务接受顺序决定第一次。模型选择交由后台调用通用生成服务时解析。
4. 提交后发出唤醒通知。通知失败不能让已接受 Run 失败，任务表仍是调度依据。

标题完成提交同时检查任务令牌、来源 Run、预期修订号、当前 `fallback` 来源及未归档状态。任何条件不符都丢弃结果。模型和工具历史、成功节点、协议绑定及恢复链不受标题写入影响。

## 服务与资源归属

新增根上的 Nya 组件 `harness.session-titles`，建议实现位于 `core/session/title-component.ts`；纯摘要、提示词、校验和状态转换放在同一职责目录的领域函数中。它拥有持久任务调度、计时器和提交等待，通过通用生成调用句柄取消并等待命名。Session 提供受信内部标题操作端口，持有全部标题及任务数据，不增加 SQLite 存储组件。模型队列与 execution 归 `harness.content-generation`。

标题组件通过 `inject` 获取本轮 Session 与内容生成服务快照。`apply` 初始化并登记 Effect 后返回，后台工作不阻塞启动。标题调度首期并发为 1，每个新会话自动尝试一次，公共生成服务控制超时和共享模型并发。

提交通知用于加速调度，启动扫描与运行期有界补扫保证通知失败后任务仍能启动。建议每 5 秒检查下一批 `pending` 任务，每批最多 16 条，队列也保持有界。关闭停止计时器，并等待已接受的扫描和认领操作。

标题消费方只向公共生成端口传专用命名指令、首条原始文本的前 2000 个 Unicode 字符及附件数量，不使用主任务 Prompt 或附件正文。四协议的原生请求、终态解析和无工具单次调用统一在通用生成组件实现，标题不通过 `RunRuntime`、`RunHost` 或临时业务 Run 执行。

每次标题任务在首次异步操作前登记所有者。通用服务等待模型操作退出、关闭 execution 并释放协议租约后返回合格文本，标题再做长度与名称校验并条件提交。组件停止或依赖重启时停止调度，取消并等待生成句柄及已接受写入。关闭客户端或隐藏界面不取消服务端标题任务。

执行应用宿主同时接入 Run 与通用生成准入的停止保护。标题任务的认领到最终提交另按现有业务活动约定保护，不能在生成返回后提前释放。命名仍在运行时，停止或重新装配 Agent 遵循现有忙碌规则；整根关闭取消并等待。若后续要求停止 Agent 时直接取消命名，需显式扩展可取消后台业务活动契约并补充测试，不能把持久写入伪装成 `blocking: false` 的只读观察。

标题组件监听应用安装的取消信号。宿主关闭准入时同步停止认领并取消生成句柄，随后由根清理等待退出和提交，最后释放业务活动保护；不能在根清理前等待 `app.activity` 清空。通过实际注入依赖让标题调度先于内容生成、Session 和存储退出，不手工复制生命周期图。

## 手动改名与客户端同步

Session 增加 `renameSession(sessionId, title, expectedRevision)`，经 harness server API、HTTP 和客户端代理白名单暴露。保存成功时设置 `manual` 来源、递增修订号并废弃后台任务；通过通知取消仍在运行的命名调用，晚到结果由条件更新拒绝。旧 `dialogue-v1` 会话与归档会话保持只读。

会话菜单增加重命名入口，输入框保留用户编辑内容。若保存冲突来自自动标题抢先完成，客户端读取最新元数据，在来源仍为 `fallback/generated` 时用新修订号重试一次。若已经是 `manual` 或再次冲突，则展示冲突并保留输入，不覆盖其他用户的人工名称。首期人工来源不可自动重置，不提供清空名称后重新生成的隐式行为。

新增执行设备级轻量 Session 变更 SSE，例如 `/session-changes`。当前 Run 变更流最多订阅四个已打开面板，不能用于覆盖未打开的侧栏会话。新流只通知 Session ID、Project ID、标题修订号与变更类别；每个正在展示会话列表的执行设备维持一条连接，按 Session 合并事件并有界刷新。

初次连接、重连和实例变化后重新读取已加载项目的会话列表与已显示归档列表。客户端只对 `title/titleSource/titleRevision` 按标题修订号合并，使侧栏、面板标题、分屏标签和归档视图使用同一个最新值，避免已打开面板的旧标题覆盖列表新标题。选模、归档等其余 Session 字段沿用权威读取与请求代次保护，不能用标题修订号判断其新旧。所有更新固定连接版本和 `instanceId`，不跨执行设备套用。

## 迁移与恢复

迁移将既有会话当前派生标题固化为 `fallback`，保留已有最多 120 字符的显示值，不批量发送模型请求。旧 Run、节点和原生历史 JSON 保持原样；空会话仍为空。新接受的首次 Run 才创建自动任务。

启动可继续尚未开始的 `pending` 任务；上一代已经开始的 `running` 任务结算为 `interrupted`，保留摘要，不自动重放可能已计费的请求。正常停止时尚未开始的任务保持 `pending`，已开始任务在等待退出后结算。归档、人工命名和任务令牌共同阻止旧代结果写回。

首期不包含批量补生成旧会话、自动重试、定期重命名、标题历史或读取附件正文。以后若增加显式重试，应创建新的任务令牌并继续使用同样的修订号保护。

## 实施顺序与验收

| 阶段 | 改动范围 | 验收结果 |
| --- | --- | --- |
| 一 通用生成底座 | Models 完整响应模式、内容生成组件、用途设置和 Web 选模 | 四协议非流式；默认与用途覆盖明确，由多个功能复用 |
| 二 持久标题 | `session/domain.ts`、`port.ts`、`sqlite-records.ts`、Session 组件、v9 迁移 | 列表与详情读取持久标题；旧数据显示保持一致 |
| 三 接受与调度 | 首次 Run 接受事务、内部标题端口、标题组件、公共生成接入及宿主活动保护 | 不点开会话也创建任务；并发与幂等只创建一次；失败保留摘要 |
| 四 公共接口 | 重命名、Session 元数据、HTTP、代理及新 SSE | 人工名称优先；断线后读取列表可恢复最新状态 |
| 五 Web 接入 | 会话索引、面板、分屏、归档、会话菜单及工作区设置 | 未打开会话自动更新；刷新、多设备与多个客户端显示一致 |
| 六 文档与验证 | 组件手册、模块导航、部署与行为测试 | 完成针对性验证，再通过根 `npm run check` |

行为测试至少覆盖：同时接受两个根 Run、重复幂等键、首 Run 失败或取消、四协议普通标题、无文本附件、搜索配置跳过、模型配置失效、人工改名竞态、归档竞态、旧代结果丢弃、超时与取消后实际退出、协议注销和依赖重启、v8 与旧 `dialogue-v1` 迁移，以及关闭时等待数据库提交。不得以标题调用生成业务 Run 或可恢复节点。

浏览器验收使用从未打开的会话列表，观察摘要到生成标题的变化，再刷新和重连；同时检查分屏、人工改名及两个客户端同步。新增组件实际实现时补独立手册并更新 [组件清单](modules/README.md)、[项目与会话模块](modules/sessions/README.md)、[执行协作](harness-server-components.md) 和 [Web 客户端设计](web-client-design.md)。
