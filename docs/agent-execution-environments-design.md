# Agent 执行环境管理设计

Personal Agent 与 Anybox Harness 在各自执行端采用共享环境管理组件。本文保留设计时的取舍与验收标准。实际接口、状态与恢复边界见[执行环境授权组件](modules/tools/execution-environments.md)。

实现对搜索目标采用保守的身份规则。提供方配置产生新版本（含 Key 轮换）后，要重新授权该目标。普通会话已固定工具声明且无法证明原绑定时，历史仍可查看，新建会话可以使用当前授权。存储升级与备份要求见[执行库兼容规则](modules/infrastructure/local-sqlite.md)。

## 用户配置的是什么

用户在某个执行端打开「执行环境」，看到可用环境、每个环境提供的工具、授权来自执行端还是资源所有者，以及实际会在哪里执行。为某个 Agent 配置工具时，先选环境，再选该环境内的工具。开始一轮对话时，应用能够回答三个问题：这次向模型提供了什么，每项工具属于哪个环境，调用会到达哪个资源。

例如，一个项目绑定到「办公室 Mac」的 Computer。用户只给研究 Agent 开放文件读取，又给它开放示例「资料库」环境的检索。该 Agent 可以读办公室项目和检索资料库。另一台机器即使提供相同的读取工具，也需要自己的绑定和授权。关闭办公室 Mac 后，资料库仍有自己的可用状态；涉及该 Mac 的新操作须报告原目标不可用。撤销文件读取时，之前的读取结果保留在会话历史中。

这里有一个容易混淆的细节。**Computer 是工具契约的提供方，某台已附着的机器是具体执行环境，工作目录是环境中的资源。** 同一个环境可以有多个工作目录。同一套工具代码可以服务多个环境。模型在某次 Run 中看到的每一项工具必须有唯一的环境归属。现有接口分别用 `computer`、`attachmentId` 和项目的 workspace 信息表达这三层。 [Computer 执行环境](modules/computers/environments.md)。

## 模块放在哪里

建议建立可选的执行环境包。Personal Agent 和 Harness 各自在**自己的执行端**安装一个环境管理组件，复用相同的管理代码。需要一个有生命周期的组件，是因为它拥有可变授权、准入与在途工作的协调。目录校验、选择计算和历史解码继续用纯函数。每个服务进程沿用现有 Nya 根，由应用通过服务绑定注入本应用的存储与提供方。环境、项目和 Run 都是数据或运行句柄。

| 所有者 | 管辖的事实及资源 |
| --- | --- |
| 环境管理模块，每个应用执行端一份 | 受信提供方目录、环境身份到提供方的绑定、Agent 授权与修订、设置投影、为 Run 解析唯一工具来源、准入和撤权进度。 |
| Agent、Projects、Session、RunRuntime | Agent 和项目身份、工作区绑定、会话与 Run 快照、工具调用意图及观察、Run 取消与结算。Session 维持唯一的 Run 事实账本。 |
| 具体提供方 | Computer 继续拥有附着、设备上限、进程及执行账本。资料库拥有资料。Models 驱动拥有协议编码、模型凭据、网络请求和原生记录。 |
| 应用客户端与 Anybox 宿主 | 客户端持有本应用的执行端连接和设备访问凭据。宿主承载应用，协调应用启停、版本与退出。 |

同一执行宿主可承载两款应用，两方分别保存授权。配置一款应用只能授予其自身可委托的能力。若产品以后要求“登记一台机器，两款应用各自申请使用”，需要单独定义资源所有者、跨应用身份、委托及撤权。这里先采用已有的应用隔离边界。 [客户端业务归属](application-client-isolation.md) · [Personal Agent 资源归属](modules/personal-agent/runtime.md)。

```mermaid
flowchart LR
    settings["环境与 Agent 设置"] --> manager["本应用执行端的环境管理模块"]
    manager -->|"授权和目标绑定"| run["Session / RunRuntime"]
    run -->|"函数调用"| gate["按本轮绑定检查当前准入"]
    run -->|"模型请求"| gate
    gate -->|"稳定操作 ID"| worker["Computer 或资料库提供方"]
    gate -->|"获准的托管工具"| models["Models 协议驱动"]
    models --> provider["模型提供方"]
```

## 身份、数据和管理接口

| 事实 | 建议保存的位置与内容 |
| --- | --- |
| 工具契约 | 受信代码声明提供方、契约版本、工具 ID、版本、模型名称、完整定义和执行方式。通用函数契约沿用 `@anybox/tool-api`。托管工具以受信协议映射标识，不伪造函数参数或 scope。 |
| 环境实例 | 以应用、执行端实例与稳定环境 ID 定位。Computer 引用已有附着 ID 与授权 epoch，资料库引用该提供方的稳定资源身份。名称用于展示。重新附着同名机器会产生新授权对象。worker 的 boot 标识本次进程，Run 的 owner epoch 控制账本写入；正常重启后分别核对可用性与原操作归属。 |
| Agent 授权 | 应用执行库保存 Agent、确切环境或明确的“项目已绑定 Computer”选择、允许的契约及版本、授权来源、修订和状态。使用项目绑定的授权还须限定可委托的附着范围，当前项目只解析到该范围内的一台机器。新增版本或新附着身份需要重新检验授权。 |
| Agent 偏好 | 独立记录 Agent 在获准的环境和工具中想选用的子集及偏好修订。恢复偏好、导入模板或再次保存旧表单，都只修改偏好。 |
| 本轮工具绑定 | Session/Run 的版本化记录保存实际模型名、工具和环境契约、确切目标身份或提供方绑定引用、所用授权修订和可复核的定义。Computer 的既有操作账本继续保存实际启动后的 worker、工作区与 scope 身份。模型供应商连接身份可保存非秘密引用。 |

以托管搜索为例，设置里可以列出“提供方 A 的 Responses 搜索环境”。授权对象固定到本应用的提供方配置 ID、服务身份、协议和受信工具契约。相同提供方内换模型时，再检查新模型的能力与参数。相同服务身份下轮换 Key，由 Models 按原规则创建新 execution；改连另一提供方或服务地址须重新确认环境身份。授权记录只引用非秘密身份。

管理接口按下表区分操作者与写入事实。此处的操作者使用应用已认证的管理入口。环境工具只接受执行请求，无法通过模型参数签发授权。

| 操作 | 写入与权限 |
| --- | --- |
| 查环境、查 Agent 工具 | 返回契约、观察、可委托上限、当前授权、偏好和受限原因。读取保持无副作用。 |
| 授予、扩大或重新授权 | 执行端的受信管理者从资源所有者已委托的范围内签发，保存授权来源、请求 ID 与预期修订。同 ID 同内容返回原结果。重新授权产生新修订，旧在途工作只能按原身份收尾。 |
| 保存偏好 | 单独按偏好修订比较并写入；越出当前授权的选择显示受限。 |
| 收紧、撤销及查询进度 | 使用授权修订串行提交，持久记录请求 ID、范围、排空结果。重复请求只观察原操作。修订冲突返回当前版本。 |

新增环境由受信提供方注册或复用其配对流程。设备令牌、附着凭据和模型 Key 继续由各自凭据库保管。

模块提供两项内部能力。Session 在自己的事务里读取同一执行库的授权修订并固定工具绑定，必要时用预期修订重试准备。RunRuntime 与协议请求边界凭该绑定取得只对本次操作有效的准入；只能在应用本代使用。调用方传递操作身份和输入，目标身份从已保存绑定解析。实际调用、取消、查询和 scope 关闭继续走原提供方。模块通过受信组合接入，应用层对外的 HTTP 仍在各自命名空间内。

## 一次 Run 怎样使用环境

1. **解析并声明。** 根据会话规则、Agent 选择、项目绑定、实际授权、提供方契约和模型协议求交集。普通函数需要模型具备函数调用能力；托管搜索按其协议能力单独判断。已明确不支持的能力给出原因。能力观察过期或未知时保留原兼容路径，在实际调用前向权威提供方核验。版本或目标身份无法证明时，拒绝需要该绑定的运行。空工具集仍可执行兼容的文本对话。
2. **固定唯一来源。** 一个 Run 可同时使用 Computer 和资料库。首版沿用所选函数工具 ID 和模型名唯一的约束，并检查托管工具保留名。不同实例可以分别提供 `read_file`；同一 Run 同时选择造成歧义的两项时，在发送请求前指出冲突来源。项目绑定 Computer 时，整轮只有该项目的 Computer 目标。将来支持同时操作两台同类设备，需要持久化“模型别名 → 原工具名及实例”的映射，并让所有协议与恢复路径可验证该映射。
3. **执行函数。** RunRuntime 先校验整批调用的名称、参数、授权和原始绑定，再由 Session 在副作用前保存稳定操作身份及意图。每项实际分派还要取得当前准入，避免批次预检后恰好撤权。提供方校验目标与自身权限才开始工作。若执行中途撤权，已执行和未执行的部分分别记实。工具结果可以先返回，调用的 `done` 和 scope 的实际退出用于最终结算。 [现有 RunRuntime](modules/execution/run-runtime.md)。
4. **执行托管工具。** 对使用该模块的 Agent，每次模型出站请求只能携带本轮授权的托管工具。模型设置表示提供方能力和配置上限。协议驱动从已核准清单构造最终 `tools` 字段，包括空集合处理；旧参数、缓存前缀与原生续轮均经过同一出口。Responses 的搜索与 Anthropic 的搜索分别绑定到当轮确切的模型提供方及协议。供应商可以在一次请求中自行发起多次搜索，因此可授权和取消的粒度是**一次携带该能力的模型请求**。搜索事实、引用与未知结果沿原生记录保存，RunRuntime 不生成虚假的本地工具调用回执。
5. **恢复。** 已保存观察直接复用。有意图、无观察的函数操作，仅允许支持 `observe-existing` 的原提供方根据原操作 ID 查回。恢复先复核所有者和环境身份；离线、重新配对或出口结果不明均保留原事实。模型请求或托管搜索的外部结果未知，沿已有中断恢复规则处理。恢复、撤权清理及查看历史使用独立于新工作准入的受限入口。

Models 可通过可选的受管执行入口接收已解析的协议工具清单及逐请求准入句柄。清单须参与 Run 快照和原生上下文兼容比较。发送前若准入修订失效，取消受影响的请求或 Run，并按会话兼容规则准备下一轮。通用 Models 只消费协议工具与准入结果，Agent 身份及授权持久化留在应用端。对最终请求体的断言必须覆盖清单为空时展开原模型参数的路径。 [Models 原生入口](../packages/models/src/component.ts) · [实际请求构造](../packages/models/src/execution.ts)。

每次发送前比较**实际要暴露的完整工具清单**，含本地函数与托管工具。如果普通会话冻结的声明含已撤销工具，且原生协议要求续轮沿用原声明，发送前返回“会话工具授权已变更”，保留历史并提示新建会话。支持从应用历史重建的连续会话可用新声明准备下一 Run。即使模型给出一项在旧轮次看见过的工具名，函数实际分派仍须持有本轮的当前准入。

## 改偏好、撤权与关环境

“下次希望给 Agent 哪些工具”和“从现在起禁止使用某项能力”在界面里必须是两种操作。前者决定将来的声明，后者约束实际执行。设备所有者设定的目录与工具上限始终是实际准入条件；现有 Computer 的目录限制作用于项目和工具接纳，命令具有运行账户的操作系统权限。界面应准确显示该环境的隔离能力。 [Worker 权限语义](computer-worker-management.md)。

| 操作 | 建议生效时机及可见结果 |
| --- | --- |
| 保存展示给模型的工具偏好 | Harness 和普通项目 Session 从新建会话起生效。Personal Agent 连续会话默认保留已选环境集合，下一 Run 读取新的环境内工具偏好。建议在管理设置提供“应用到此连续对话的后续运行”，以便新建时环境为空的 Agent 也可以在原对话中显式采用新环境。 |
| 扩大授权 | 按新修订生效，已接纳 Run 的声明只可保持或受实际撤权限制。旧快照中的空环境保持原义。 |
| 收紧或撤销授权 | 在应用内先封闭受影响的准入，持久化新修订并登记待排空操作，再取消已接纳的相关 scope 或模型请求。无法隔离单次工作时取消受影响的整轮。分别报告“已禁止新调用”“正在退出”“已确认退出”或“退出未确认”。 |
| 移除环境、断开连接或关页面 | 移除环境走撤权流程，保留历史身份用于查询和清理。网络断开记录可用性变化。页面退出只释放观察。独立 worker 的生命周期归其所有者。 |

新分派与撤权必须由同一执行端所有者串行裁决。分派在放行外部请求前同步登记受保护的在途句柄或预留；撤权封闭准入后等待已越过该点的工作。撤权事务写入失败时报告保存失败，在当前代保持受影响范围封闭，持久化成功才确认“已禁止新调用”。崩溃重启先加载持久修订和待排空记录，再开放新调用。旧代无权写入新代账本；当前所有者可凭原 ID 和已核对的身份向提供方查回迟到回执。设备上另有权限变更时，以设备接纳事务中的检查为准。网络分区期间执行端可以确认本侧已拒绝新工作，远端真实退出则等待可验证回执。关闭本地模型连接只能证明本地请求退出；已交给供应商的副作用需要单独标明可观察范围。

连续会话的显式采纳操作比较会话环境版本和当前授权修订，向前追加一个环境集合版本。下一 Run 在接纳事务里固定采用的版本和工具。与变更并发的 Run 只能采用事务顺序确定的一套完整声明。原工作目录、已接纳 Run 的初始化及已完成工具结果各自沿原身份读取。这样也有一条从“空环境”到“获得第一个工具”的完整用户路径。

## 界面归属

- **管理连接**回答“我要连接哪一个 Agent 执行端”。保留地址、访问令牌、连接检查与应用启停。设备所有者从「执行环境」管理本机 worker，即使客户端尚未连接 Agent 执行端。
- **执行环境**回答“这个执行端的 Agent 能使用哪些资源”。按实例列出归属、来源、授权、最近观察状态及工具。Computer 从这里生成附着码，设备侧消费并设定上限。界面标明“执行端本机”和“客户端所在机器”。
- **Agent 工具**回答“这个 Agent 能用哪些环境、其中哪些工具”。按环境分组展示。保存前说明影响新会话还是下一 Run，撤销权限显示影响的工作和排空结果。Run 轨迹能从一项工具定位到当时的环境及目标。

## 迁移与验收

| 阶段 | 交付条件 |
| --- | --- |
| 1. 统一读取和契约 | 从两款应用已有目录、项目绑定、授权和 worker 观察构造只读投影。用内置 Computer 及资料库示例跑相同行为契约。列举环境、打开设置、加载历史均无工具副作用。 |
| 2. 接入授权和函数分派 | 首次写入新授权前验证所有支持入口的最低执行端版本约束，包括独立入口；旧执行端能接管同库时须推迟切换。由同一写入者事务导入原设置、记录来源版本；旧客户端设置写入也由该组件仲裁。缺省 Computer、显式空集、已知的 Agent 选择、当前已批准目标及退役兼容分别处理。只为可证明的既有使用范围生成迁入授权；无法确定时列出待确认项。旧快照按原格式读，仍可查看历史，超出当前授权的新调用被拒绝并给出原因。 |
| 3. 收口原生搜索与全部出口 | 已有模型搜索设置列为待授权，用户可提前指定允许使用它的 Agent，切换时缺省空授权。新会话采用显式选择。旧项目 Session 的环境集合保持冻结，使用新增搜索环境须新建会话。Personal Agent 切换前交付连续会话显式采纳新环境版本，并用有历史搜索的旧样本验收。过往 Run、引用和搜索记录保持可读。用真实驱动和受控 HTTP 对端截取请求体，覆盖首次、续轮、Anthropic 暂停续轮、换模型及恢复。两条出口均受控后才宣称“全部工具归环境管理”。 |
| 4. 切换设置与恢复演练 | 用旧库副本演练升级、崩溃恢复与两应用同根运行。取得旧服务所有者真实退出证明后再交接。外部结果未知时，新所有者封闭受影响范围，仅对原操作对账。恢复备份须离线核对最新撤权和在途操作；无法证明的授权保持封闭。 |

实施验收应能直接观察以下结果。

- 同一应用给 Agent A 授予一个环境的读权限，Agent B 保持空授权。另一应用、同名机器、新附着身份以及较新契约版本都不能继承这次授权；另一个应用能独立退出和恢复。
- 同一 Computer 契约用于两个项目时，调用和恢复均命中各自原目标。目标掉线时无替代派发。报告未知仍可以查看设置，设备拒绝越权调用。Personal Agent 的连续工作目录沿用现有执行端本机绑定。
- 空环境＋开启过搜索的模型，在实际出站请求中同时缺少可调用函数与托管搜索。显式授权后只出现匹配协议的那项工具；收紧授权与并发续轮竞态只有一个明确次序。历史中已发生的搜索结果仍可浏览。
- 并发改授权、整批调用的后项被撤权、worker 已领取但回执丢失、环境重配、应用重启与清理失败，均能查出原操作、原目标和真实退出状态。已完成的副作用不会因恢复再次执行。
- 分别验证普通会话、连续会话、旧初始化和已有在途 Run。配置偏好、公示给模型的工具、当前允许执行的工具可分别解释；原生上下文仅在实际工具声明与目标兼容时复用，否则走应用已有的历史重建或显式不兼容路径。

现有回归入口包括 [环境注册与碰撞](../tests/tool-environments.test.mjs)、[运行与恢复](../tests/tool-environment-runtime.test.mjs)、[旧清理身份](../tests/tool-environment-history.test.mjs)、[Computer 断连与故障](../tests/computer-unit-faults.test.mjs)、[原生协议](../tests/native-protocol-agents.test.mjs)及 [Personal Agent 连续历史](../packages/app-personal-agent/tests/continuous-history.test.mjs)。这些测试提供现状对照。新权限与真实出站请求的联合用例属于实施验收。

## 建议优先评审的三项决定

1. **环境的使用范围。** 本稿建议两款应用共用模块，各执行端持有自己的实例和授权。跨应用一次登记再分别授权是另一种产品体验，需要明确由谁运营共同的资源目录。
2. **同一轮操作多台同类机器。** 首版建议一个项目绑定一个 Computer，同时允许组合工具名无冲突的其他环境。需要同时向两台机器发命令时，产品要让用户与模型都能辨明目标，并把该选择固定到历史里。
3. **托管搜索的授权迁移。** 建议把已有模型搜索设置作为能力上限，由用户显式选择可用它的 Agent。切换将改变部分已有会话的搜索可用性，优先用有历史搜索记录、空环境及跨协议续接的样本评审。

Claude Agent 的 SDK 工具由其独立运行时提供。若它后续接入，应单独证明环境授权能约束 SDK 的工具发现与实际执行，再声明覆盖范围。 [Claude Agent 运行边界](claude-agent-design.md)。
