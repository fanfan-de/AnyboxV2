# Anybox static distribution composition

`@anybox/distribution` holds the first-party client combination of Anybox Harness, Claude Agent, Personal Agent and explicit native adapters. Personal Agent currently runs locally in the client role; the execution combination remains Harness and Claude Agent. It owns the CLI and desktop entry configuration, application-specific smoke diagnostics and the compatibility `createHarnessServer` composition. It is not another user application or a Nya Context.

The host package does not import this package or the applications. This package explicitly selects application registrations and platform adapters, while the host and Nya continue to own their existing lifecycle and cleanup boundaries. Database locations, environment variables and application IDs remain compatible. Each application owns its business tables and credential namespace; former shared connection records and credentials are read-only import sources.

The root scripts preserve the existing commands (`client`, `harness:server`, `computer:worker`, `web:local`, `desktop:dev`). Build this package after its public dependencies using `npm run build --workspace @anybox/distribution`; its package tests verify that CLI help does not start services.

`npm run personal-agent` starts the regular Anybox shell with only Personal Agent and prints its direct local URL. Its default data file is `./data/personal-agent.sqlite`, selected by `ANYBOX_PERSONAL_AGENT_DATABASE`; `ANYBOX_PERSONAL_AGENT_MODELS_CONFIG` selects the separate Models JSON file and `ANYBOX_WEB_PORT` selects the local port. Models and its business implementation load only after opening this application. See [the application manual](../../docs/modules/personal-agent/README.md).

Node release and desktop staging keep the existing static combination. D0b activates providers only for actual consumers. D1.2 independently builds an empty `@anybox/host` product and complete signed application archives with `npm run artifacts:build`; this package is excluded from that minimal host closure. D1.3 adds local file installation and explicit recovery through the host package manager, using a separate registry and externally configured publisher trust. Successful imports stay installed/pending and never start application business or change this static catalog. Runtime activation remains D1.4, uninstallation D1.5, and online download D2. See [the design](../../docs/application-packages-design.md) and [artifact contracts](../../docs/modules/package-management/archives.md), plus the [local installation manual](../../docs/modules/package-management/installation.md).

`web:local` now assembles client and execution components in one Node.js process and one Nya root. It retains the client/execution listeners, databases, targets and managed pairing identities. The independent `client`, `harness:server` and Computer worker commands remain available. The enclosing composition owns final root disposal; explicit Nya service bindings keep execution resources distinct from client applications.
