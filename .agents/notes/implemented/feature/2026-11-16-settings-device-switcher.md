# Agent Note: 在设置分类中展示并切换管理设备

Status: implemented

## 问题

设置窗口左上角的“执行设备：本机”难以说明模型、Prompt 等设置的归属，且设备切换入口位于弹窗外。用户希望直接看出正在配置哪台设备，并在设置中切换；连接管理和归档会话又具有跨设备范围，不能让同一提示误示为仅针对当前设备。

## 决策

已确认采用右侧当前分类标题旁的设备选择器，窗口保留“Anybox Harness 设置”大标题。会话、模型、工具、Prompt 和执行环境分类列出全部已保存设备；连接与归档分类显示“所有设备”。设置与侧栏仅以已确认的本机实例身份显示“这台电脑”，其他设备保留保存名称，不根据名称或地址推断本机。

设置内设备切换复用现有目标路由和完整表单离开保护，覆盖隐藏分类及连接表单。未保存修改或进行中的设置操作阻止切换，恢复原选择、保留输入并提示用户保存或通过现有入口明确放弃修改；若阻塞修改位于其他分类则展示该分类。允许切换后等待旧页面实际清理及固定设备写入退出，恢复已打开弹窗、当前分类和切换控件焦点。未启动或离线目标仍列出，只显示对应不可用状态，不因切换自动启动或回退到其他设备。

切换通过侧栏与设置共用的连接选择入口；准入后冻结旧界面和模态框，父层保存临时视图状态并等待原页面真实退出后再挂载。执行环境及本机 Computer 管理新增进行中操作检查；只读设备状态探测增加每台设备 15 秒总预算，超时保留连接并显示暂时不可用，不给显式启动等写操作增加超时或重试。

## 备选方案

讨论过只将原副标题改成“正在设置：本机上的 Anybox Harness”，或仅在分类标题旁显示不可切换的设备标签。这些方式能改善归属表达，但仍须关闭设置才能切换设备，因此未采用。保留“执行设备”也容易与模型推理位置或远端 Computer worker 的实际执行位置混淆，本轮按管理对象展示设备。

## 影响与代价

新增设置内设备切换入口及分类范围展示，沿用已有连接、实例身份和数据归属，不新增配置同步、服务启动或模型执行能力。需要在工作区重建时恢复弹窗、分类和焦点，并确保设置请求始终固定到原设备；不自动提交、丢弃草稿或取消已接纳业务。原设置侧栏“工作区”标题的删除继续保留，本轮调整其后独立的设备范围交互。

## 验证

- 使用本机 Node 24.16.0 执行 `npm run build --workspace packages/app-harness`，TypeScript strict 编译及应用资源构建通过；`node scripts/verify-web-assets.mjs` 验证新增浏览器模块注册与静态依赖图通过。
- `node --test` 定向运行 `settings-client`、`desktop-local-pairing-ui`、`session-defaults-client`、`tools-client`、`units-client`、`archive-client`、`harness-navigation`、`harness-client` 及包内 `package-assets` 共 9 个测试文件，59 项通过。覆盖分类范围、选择回退、事件清理、状态/焦点恢复、隐藏连接草稿、无隐式启动、进行中的附着/附着码操作和写入真实退出等待，以及编辑或换分类后清除过期的切换提示。
- 内置浏览器使用一次性数据库、内存凭据和禁止模型网络调用的多设备实例：确认切换后保留 Prompt 分类、打开的弹窗和设备选择器焦点；隐藏的 Prompt 和连接草稿均阻止切换、保留原目标和输入并展示阻塞分类；显式放弃后可切换。
- 另用两个真实 Products 宿主的隔离实例，按本机 instanceId 显示“这台电脑”，显式停止测试远端 Agent 后切入其 Prompt 分类，仍显示未启动占位并可切回本机，未自动启动目标。“管理连接”按所有设备展示。
- 默认窗口及 390px 窄屏截图检查通过；390px 下设置内容 scrollWidth 与 clientWidth 相等，设备选择器位于可视范围。Chrome 自动导航被既有来源保护拒绝后改用内置浏览器，没有修改安全策略。
- `git diff --check` 和本记录链接检查通过。未执行全仓测试、真实跨机网络、缓慢响应超时注入、真实模型调用及其他平台桌面验收；未重启用户原有开发实例。
