# Agent Note: 模型按无新内容计时并保留失败输出

Status: implemented

## 问题

用户报告 Agent 在持续输出时仍中途失败，要求 30 秒按没有收到新内容计算，并保留失败前已收到的内容。原模型交换使用固定总时限，长流式响应会被中断；失败后的部分原生内容及普通对话中的临时输出也可能丢失。

本记录于 2026-11-11 补录此前同一聊天已完成的修复，依据当前源码、行为测试和本机检查输出，不重构更早的失败历史。

## 决策

复用连接的 `timeoutMs`，将每次模型交换的响应等待改为原生事件之间的无内容等待时限。每次驱动交付已接纳的原生事件先续期，再通知可选观察者；没有观察者或观察者失败脱离不影响计时。首次事件前的等待包含资源读取和请求发送，后续交换重新获得等待额度，持续事件允许生成总时长超过 30 秒。

续期对象是驱动交付的协议事件，包括正文、推理、工具参数和已接纳状态事件，不等于任意网络字节。SSE 注释、未组成事件的分片及驱动忽略的 Anthropic ping 不续期。complete 模式没有增量事件，完整结果仍需在首次等待内完成；工具执行与连接发现/检查保留各自时限。

四种 Models 驱动在超时、取消、断流或解析失败时，将已接纳的原生内容保存为内部 diagnostic；不保存原始错误帧，不把部分结果提交为成功上下文。取消错误规范化保留诊断，Models 在退出前执行既有字段及捕获凭据脱敏。Anybox Harness 持久保存失败诊断，Web 在当前父节点保留临时输出直至耐久诊断替换，重新打开也可读取，并标注未完成状态。

## 备选方案

**延长固定总时限。** 仍会截断更长的正常流式生成，且无法表达无新内容时才取消的要求，因此改为每次事件续期。

**仅保留浏览器临时帧。** 刷新、关闭控制器或服务重启后无法可靠读取失败输出，因此由 Models 保存协议诊断、Session 持久化、Web 使用已有白名单投影。

**将部分响应当作成功历史继续执行。** 未完成的工具参数和原生停止状态不具备成功语义，因此诊断不能成为成功节点、祖先上下文或可执行工具调用。

## 影响与代价

连接表单明确显示“无新内容超时（毫秒）”，既有配置值继续使用，不新增整个 Run 的统一总时限。30 秒来自被排查连接的设置，并非强制改写所有连接。超时发出取消，实际资源退出仍需等待；响应计时在协议 operation 的 `result` 结算时停止，不承诺 HTTP 终态一到就立即停表，内置图片包装会等待内部清理后结算外层 result。

失败内容用于查看而非恢复，失败 execution 的记录链不可恢复。流式进度不保证每个 token 在任意进程强杀前落盘；既有失败 Run 已丢失的内容不能补回，旧请求不会自动重放。浏览器投影仍受白名单和展示长度预算裁剪，不承诺无限展示所有耐久原生内容。

## 验证

Models runtime 模拟计时覆盖持续事件超过总阈值、最后事件后重新计满等待时限、无观察者与观察者异常、迟到事件及真实退出等待；本地 HTTP/SSE 集成覆盖 250 ms 无事件阈值下持续输出约 640 ms 仍成功。

四协议失败诊断测试覆盖 EOF、读取失败、无效帧、超时和取消，以及 Responses 直接 delta 流；协议 Agent 集成覆盖失败内容持久化、HTTP 读取和宿主重开，同时验证不执行工具分片、不创建成功节点和不污染新根分支。Web 测试覆盖失败/取消/中断的内容保留、耐久替换、晚到帧隔离和分支位置。

2026-11-11 已完成的根 `npm run check`（包含后续工具纠错的当前源码）结果为 2206 项测试、2185 通过、21 跳过、0 失败、0 取消。上述行为由模型替身、受控时钟与本地 HTTP/SSE 验证，不代表新增真实提供方或全平台验收。
