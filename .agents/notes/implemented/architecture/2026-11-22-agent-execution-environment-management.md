# Agent Note: 设计 Agent 执行环境管理模块

Status: implemented

## 问题

用户希望每个提供给 Agent 的工具都有执行环境归属，并由专门模块管理。两款应用已有受信工具环境、Computer 附着和协议原生搜索，声明工具与授权执行分布在不同路径。

## 方向

已确认的是工具的环境归属与统一管理目标。本轮形成架构提案。建议两款应用复用规则和契约，在各自执行端装配有状态服务，以一次工具调用或一次带托管工具的模型请求为准入边界。产品选择与阶段验收见设计稿。

## 备选方案

比较共享界面、应用内复用模块和跨应用常驻环境服务。界面复用不能覆盖服务端发起的调用。跨应用常驻服务需要新的身份、授权和离线恢复契约。提案从各应用独立持有状态开始。

## 影响与代价

实施涉及应用自己的设置与存储、Session/Run 的历史兼容、Computer 附着及 Models 协议请求。业务授权变更需要与在途调用、排空和恢复协调。本轮交付范围为设计与评审依据。

## 验证

已核对两款应用的工具声明与执行、Computer 附着、Personal Agent 连续会话及 Models 原生搜索组包。用 Node 24.22.3 和本机已有构建产物运行八个现行测试文件，共 102 项通过，覆盖环境注册、运行与恢复、旧清理身份、Computer 投影和撤权失败、原生协议、连续历史与 Models 协议。没有重新构建工作区。这是当前行为的回归基线；提案中的统一授权、托管工具准入、会话迁移和撤权竞态留待实施验证。

设计稿与本记录的 24 个本地链接、文档首页导航及空白检查通过。对照评审已补入授权与偏好的独立修订、连续会话显式采纳、真实出站工具清单以及旧代迟到回执的写入边界。
