# Agent Note: 每个模型只保存一套参数

Status: implemented

## 问题

每个目录模型可保存一条基础配置和多个参数预设。用户希望每个模型只出现一次，直接编辑这一模型的参数。

## 决策

共享 Models 按模型定义 ID 保存唯一的本地模型设置，删除基础配置与预设的区分。两款应用在模型列表中直接编辑参数。目录来源继续拥有公共定义，编辑写入本地设置。旧可执行模型 ID、固定定义版本和原生恢复信息沿用。自定义模型使用同一提供方已知的远端 ID 时，界面打开已有模型，服务端拒绝重复定义。

## 备选方案

只删除另存预设按钮会留下可创建多套参数的接口与存储约束。用户确认同时调整共享 Models 和两款应用。

## 影响与代价

模型管理 HTTP 切换为 `/models/settings`，存储升级到 JSON v3 和 SQLite v5。旧模型有多条设置时，迁移采用唯一启用的一套，其余版本保留在历史中。多套启用或都停用时原文件保持原样，由用户明确选择。已退休的可执行模型 ID 保留给旧历史，重新添加模型时建立新的可执行身份。

## 验证

- 隔离副本的 36 项存储、迁移和续接测试通过。另有 128 项 Models 定向测试通过，覆盖并发创建冲突、设置删除后的历史身份及源数据刷新。
- 两款应用的模型编辑和自定义模型入口通过 Chrome 冒烟测试，临时 HTTP 宿主验证保存修改后原会话保持选模。
- 只读预检本机配置，Harness 的 37 个模型以及 Personal Agent 的 2 个模型均保留原 ID、版本和参数。当前运行实例和数据保留原版本。
- macOS 隔离副本的整仓 `npm run check` 通过，2386 项通过、18 项按平台或集成条件跳过、0 项失败。协议和迁移验证使用受控传输及替代 Vault。
