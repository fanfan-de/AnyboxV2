# Agent Note: Personal Agent 的头像导航与工作目录

Status: implemented

## 问题

Personal Agent 的对话已按 Agent 持续保存，但进入工作区仍要先选择项目，左栏也主要展示项目。用户希望去掉项目概念，左栏上方显示主 Agent 头像，下方显示其他 Agent 头像。

## 决策

在当前执行设备上用头像直接切换 Agent。设备目录首个 Agent 固定放在顶部，其余头像在下方。设置面板保留设备选择。执行端为每个 Agent 自动准备工作目录，沿用已有连续历史身份及文件和工具的目录边界。

## 备选方案

仅隐藏项目列表会让空库缺少运行入口。复用同一个全局目录会让多个 Agent 的文件混在一起，因此采用按 Agent 分配的目录。

## 影响与代价

已有连续历史、旧目录和历史对话入口均保留。升级时可接续上次选中目录的草稿，旧文件需在当前工作目录重新引用；其他旧目录保留原浏览器记录。工作目录按 Agent 身份持久保存，浏览器选择无须提供路径。旧 API 的显式目录绑定仍可读取并使用其原有历史语义。

## 验证

- Linux Node 24 全仓类型检查通过。全仓测试共 2,396 项，2,374 项通过、22 项按既有条件跳过，0 项失败。网关集成测试验证空库打开、并发及重启时的目录身份、跨 Agent 绑定拒绝、文件准备和受控模型运行。定向浏览器控制器测试验证旧目录发送的原请求查询与草稿恢复。
- Chrome 使用真实本机宿主、临时数据和受控模型。桌面和 390 像素宽屏幕验证了头像顺序、Shader 与首字头像、键盘和鼠标切换、各自对话与草稿、刷新恢复、无项目启动，以及抽屉与浮动菜单的布局。历史对话入口验证旧归档原文的只读查看、刷新后留在历史对话和点击主头像返回连续对话。
- Electron、macOS、Windows 和真实付费模型未单独验证。
