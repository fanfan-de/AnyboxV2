# Agent Note: 每个模型提供方只保存一套设置

Status: implemented

## 问题

模型设置为同一个目录提供方提供可命名的多个账户连接。用户希望在共享 Models 数据模型和两款应用的设置里一起去掉这层概念。

## 决策

在每个应用的执行端，以提供方定义 ID 索引一套本地设置。地址、协议、认证和超时按提供方管理，模型配置继续独立保存能力和参数。目录定义由来源管理，系统 Vault 保存 Key。界面从列表或目录打开已有提供方，重复创建返回冲突。移除后可以重新添加，沿用提供方身份并为新设置建立独立的恢复范围。

## 备选方案

曾考虑只简化两款应用的界面，继续维护可创建多个连接的数据结构。用户确认需要同时简化数据模型与界面。

## 影响与代价

Models 服务、两款应用和 HTTP 模型管理统一使用提供方 ID。JSON v2 和 SQLite v4 保留既有模型配置 ID、凭据引用与原生恢复身份。同一提供方存在多套旧连接时，迁移报告冲突并保留旧配置。用户可在上一版明确移除多余连接，之后重新升级。

## 验证

- 整仓构建和浏览器资源检查通过。
- 33 项存储、冲突和升级测试通过，覆盖原生会话续接、SQLite 导入源保留和重复提供方迁移回滚。
- 175 项 Harness 和 Personal Agent 集成测试与 38 项模型和会话设置测试通过。两款应用的设置模块使用受控 API 通过 Chrome 验证，包括已配置目录项、重复新增和目录缺失。
- macOS 整仓 `npm run check` 通过，2383 项通过、18 项按平台或集成条件跳过、0 项失败。迁移使用临时存储，模型调用使用受控传输与替代 Vault。
