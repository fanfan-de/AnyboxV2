# 变更方向记录（Agent Notes）

这里记录 Anybox 每次独立变更要解决什么问题、采用什么方向、为什么这样选择，以及影响和验证证据。当前功能、接口和资源生命周期在[项目文档](../../docs/README.md)与组件手册中维护，具体差异由 Git 保存。

结构参考 2026-11-11 查阅的 [DeepSeek Harness Agent Notes](https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/README.md) 和[已实施记录维护约定](https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/implemented/AGENTS.md)。Anybox 按用户要求覆盖每次独立变更，包含小改动；DeepSeek 对机械或局部调整的豁免不适用于本仓库。这里使用中文单份记录，格式和维护规则以本文件为准。

## 记录粒度与时机

一个可独立评审的变更目标对应一篇记录，目标内可以包含多个文件、提交和修正。代码、配置、依赖、脚本、资源、测试策略、文档及小型界面调整都需要记录。只读调查或未产生仓库变动的讨论无需建档。

开始工作时创建 `proposed` 记录，或更新本轮同一目标已有的记录；直接完成的小改动也可以在交付前写为 `implemented`。同一轮迭代更新同一篇，不为每次保存、测试、提交或记录自身的编辑再建一篇。后续独立变更另建记录，链接之前的相关方向。小改动可以每节只有一句，但问题、方向、影响及验证必须清楚。

只记录有依据的事实。补录旧变更使用补录日期命名，并说明原变更时间是否可确认、证据来自哪里；不推测尚未调查的历史，不将已有工作区的其他改动归入本轮。没有实际讨论过的备选方案写“未比较其他方案”，不编造评审或用户确认。

## 目录与命名

记录路径为 `{lifecycle}/{class}/YYYY-MM-DD-topic.md`。日期是首次建档日期，移动状态时保留；同日同类用清晰的不同主题名，必要时加数字后缀。只在有记录时建立对应目录，不预建空分类、年度目录或占位文件。

| 状态目录 | 含义 |
| --- | --- |
| `proposed/` | 拟议、已决定但尚未全部实现，或验证仍阻止交付的方向；正文区分已确认、待确认、已完成和剩余项 |
| `implemented/` | 本轮目标已经实现并交付；验证范围与未验证项仍需明确，不能等同于全平台或线上验收 |
| `rejected/` | 明确否决或撤回的方向，`Status` 行说明原因 |
| `archived/` | 已实施且不再指导当前开发的历史方向，保留原理由并冻结；不能当作现行规范 |

| 类别目录 | 适用方向 |
| --- | --- |
| `feature/` | 用户或模型可见的新能力 |
| `bug-fix/` | 缺陷修复、异常处理与恢复行为修正 |
| `simplification/` | 删除或简化实现、重复机制与无用入口 |
| `architecture/` | 包依赖、组件职责、协议及数据或资源归属的结构调整 |
| `process/` | 仓库治理、开发工具、构建发布流程、日常文档与编辑调整 |
| `testing/` | 测试基础设施、验证策略和独立测试覆盖改进 |

按主要目标选一个类别；修复附带测试仍归 `bug-fix`。分类表达变更方向，不建立额外运行组件，也不改变源码目录。

通过状态/类别目录浏览，用 `rg --files --hidden .agents/notes` 按日期或主题检索，用 `rg --hidden '关键词' .agents/notes` 搜索内容。不维护逐篇汇总的中央索引，避免与路径信息重复。

## 内容格式

文件以如下标题和状态开头，机器可辨认的状态值使用英文；标题和正文使用中文。

```markdown
# Agent Note: 主题

Status: proposed

## 问题

触发变更的现象、需求或约束。

## 方向

拟采取的做法及其理由；区分已决定与待讨论事项，写出关键范围。

## 备选方案

实际比较过的做法及未采用的原因；没有比较则如实说明。

## 影响与代价

用户行为、兼容、数据、资源归属、取消/退出及维护成本中相关的影响。

## 验证

拟验证的可观察行为；工作中更新实际命令、范围、结果和未验证项。

## 关联

当前组件手册、设计、源码、测试及相关方向记录的相对 Markdown 链接。
```

`implemented` 使用相同结构，将“方向”改为“决策”，写最终已经实现的行为；验证写实际事实，不能保留待执行清单冒充完成。`rejected` 保留提议内容，状态写成 `Status: rejected — 原因`。特殊技术章节可按需增加，避免复制接口、长日志、会话原文或运行截图。

## 状态变化、替代与归档

从 `proposed` 完成后移动到相同类别的 `implemented`，同步 `Status`、最终决策、实际验证和引用链接；未完成或被验证阻塞时保持 `proposed`。被否决或撤回则移到 `rejected` 并写原因。路径与状态必须一致。

已实施记录中的路径、符号、默认值和覆盖情况随当前实现维护；原始决策与理由不能被改写成后来的相反方向。后续撤销或替代另建记录，双方链接，并在旧项中明确哪些内容被替代。旧方向已无当前指导意义时可移到 `archived/{class}/`，保留 `Status: implemented`，其下一行添加 `Archived: YYYY-MM-DD`，交代替代项并修复入链后冻结。归档后不改写、移动或删除；发现错误时新建更正记录并引用原项。

变更方向记录作为简短的长期决策依据保留，不随旧实现或一次性验收材料一起删除；过期架构快照、重复手册、命令输出和专属媒体仍按[文档维护约定](../../docs/README.md#维护约定)清理。现有设计内决策表与阶段进度不搬迁、不猜测补齐历史，相关内容用链接衔接。

## 交付检查

交付前确认记录对应本轮目标，路径、状态、实际实现、链接和验证结果一致；未验证的平台、真实模型或部署效果单独说明。最终回复提供本轮记录链接。当前约束由 [AGENTS.md](AGENTS.md) 和根协作说明执行，没有自动格式门禁或自动归档器。
