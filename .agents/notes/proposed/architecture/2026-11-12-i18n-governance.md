# Agent Note: 多语言治理与分阶段接入

Status: proposed

后续方向：用户已明确采用[宿主与单应用试点优先](2026-11-12-i18n-pilot-first.md)，取代本记录中预先共享与全面工具链的顺序。曾讨论的[通用模块与 Nya 适配候选](../../rejected/architecture/2026-11-12-i18n-nya-component.md)已在本阶段不采用。原有应用资源归属及宿主/应用边界继续适用，本记录保留原提议理由，当前安排以试点方向及现行设计为准。

## 问题

用户准备为 Anybox 接入多语言治理，并确认首批支持简体中文与英语；在同一方案讨论中进一步要求宿主与应用有明确界限，避免职责越权。当前宿主与两个应用的 Web、桌面原生菜单、错误展示和格式化分散在各自入口，尚无统一翻译机制；独立应用包、持久历史和运行中任务又要求保持资源及生命周期边界。

## 方向

本轮交付[待实施设计](../../../../docs/i18n-governance-design.md)，不修改运行代码。建议宿主管理自身呈现偏好，通过可选的 application-api 读取/订阅契约发布 `preferredLocale`；各应用自行决定实际语言、回退、翻译和格式化实例，资源随确切应用版本交付。共享包只提供可选便携机制，建议本仓库采用 i18next core 与 Intl，不新增 Nya 组件或后台语言状态，也不把选用某个翻译库作为安装/生效条件。

用户要求明确边界后，方案进一步列出职责矩阵：语言端口无写入、业务或他方资源能力，宿主不扫描/改写应用 DOM，语言通知不调用应用生命周期控制；回调失败按应用隔离处理。同步说明现行同源 ESM 和同根受信代码的可达范围，`readonly`、包签名及 Electron context isolation 均不能冒充应用间恶意代码隔离；桌面偏好桥尚未设计或实现。此处是在同一待实施方案内收紧约束，没有新增权限系统或改造运行架构。

建议先建立词条、术语、类型与增量门禁，再以宿主应用管理为样板，将桌面双入口、Claude Agent 与 Anybox Harness 按功能迁移；语言切换原位更新文案，不重挂载应用。CLI 人类说明、产品通知结构化和声明式应用介绍另列阶段。除首批语言外，其余是本轮提出的建议，未视为用户已经确认的实施决定。

## 备选方案

- 集中全仓业务字典或让宿主向应用传全局翻译器：会把独立应用版本与宿主词条绑定，不采用。
- 自写替换器：复数、回退与格式化规则需要长期自行维护，不推荐；FormatJS ICU 可行，但本方案选择一套 i18next 原生消息格式，避免同时维护两种语法。
- 一次替换所有字符串、通过 reload/remount 切语言：迁移面过大，且现有页面清理与草稿保护要求不允许将其作为普通语言切换路径。
- 首期引入在线翻译平台、独立语言包或扩展安装清单：当前中英双语可随现有静态资源交付，额外分发机制与包格式调整收益不足。

## 影响与代价

后续实施会增加本地资源、类型生成、翻译审阅与 CI 检查成本。当前不改变依赖、公开接口、包格式、数据、Prompt、工具声明或运行任务。本设计特别区分 UI 文案和业务原文，保留旧历史及机器字段，并说明浏览器与桌面偏好的不同持久归属。

## 验证

已静态核对 Web mount 契约、宿主与两应用入口、错误码传输、桌面双入口、资源闭包及安装清单校验；技术候选依据官方文档。设计与治理建议尚未进行运行时、浏览器或跨平台验收。

本轮及边界细化后均尝试根 `npm run check`，当前执行环境未在 PATH 提供 `npm` 或 `node`，命令以 127 退出，未进入构建或测试。Python 静态检查通过：本轮 3 个 Markdown 文件的 111 个本地链接目标存在，Note 状态及必备章节齐全，无行尾空白；`git diff --check` 通过。两项独立只读复核及后续定向核验确认现行同源/同根受信运行边界，未将职责约束描述为已实现的权限沙箱；上述检查不代表多语言运行行为或安全隔离已经实现或验收。
